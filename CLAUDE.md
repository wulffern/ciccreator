# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

cIcCreator is a C++/Qt *layout compiler* for analog IC blocks (originally SAR ADCs). It reads three inputs and writes one output:

| Input | Role |
|---|---|
| object definition `.json` | cells, their classes, and the methods to run on them |
| companion `.spi` | SPICE netlist — **same basename** as the `.json` (`ip.json` → `ip.spi`), gives connectivity |
| technology `.json` | layers, design rules, devices (`examples/tech.json`) |

Output is a single `<library>.cic` file — JSON describing the placed and routed geometry. Since v0.1.5 there is **no GDS or SPICE output**; [cicpy](https://github.com/wulffern/cicpy) transpiles `.cic` to GDS/SPICE/SVG/Magic.

## Build

```bash
make                 # qmake6 (falls back to qmake-qt5) + make; needs Qt5 or Qt6 base
make debug           # same with CONFIG+=debug
make clean           # also cleans every tests/<t>
```

Binaries land in `release/` as `cic.<platform>_<version>` plus a `cic.<platform>-latest` symlink. `release/` is a **git submodule** (ciccreator-bin). `bin/cic` and `bin/cic-gui` are symlinks to `bin/start_script.sh`, which picks the platform binary — always invoke the tools through `bin/`, never the raw path.

`cic/src/version.h` and `cic-gui/src/version.h` are generated by the Makefile from `VERSION` and `git describe`; they are gitignored, so a fresh checkout will not compile without going through `make`.

## Run

```bash
bin/cic <object.json> <tech.json> [<output name>] [--I <path>] [--L <cic file>] [--prefix <p>]
bin/cic-gui <file.cic> <tech.json>        # legacy viewer; both args are required
```

**`cic-gui` is superseded by `cicpy gui`**, which is more advanced — it auto-discovers the tech file and dependency libraries from the IP's `config.yaml`, merges extra `.cic` libraries with `--I`, and re-runs the flow on demand (`Ctrl+R`). Prefer `cicpy gui <file.cic>` (needs `pip install 'cicpy[gui]'`). `cic-gui` is kept working but is not where new viewer features go.

`--I` adds an include search path, `--L` imports a compiled `.cic` as a library. Output name defaults to the object file's basename.

Demo targets (all write into `lay/`):

```bash
make esscirc && make view       # the ESSCIRC'16 SAR ADC
make routes  && make viewroutes # the routing/via test patterns
```

## Test

```bash
make test                       # all suites in TESTS
cd tests/sar && make test       # one suite
```

Suites are `sar` and `routes`; `sun_sar9b` is appended to `TESTS` **only on macOS** — it diffs against a checked-in golden `ref.cic` and has been observed to differ across platforms. Tests need `cicpy` (`pip install cicpy`) and `jq` on PATH.

Each suite runs `bin/cic`, then:
- `tests/check_ports.py <file.cic>` — fails on zero-area ports (a paint bug once silently emptied them).
- `tests/check_cuts.py <file.cic> [--allow N]` — fails if a via's metal does not overlap same-layer metal elsewhere, i.e. the cut connects to nothing. `--allow` is a baseline of known-harmless dangling vias, not a tolerance.
- `sun_sar9b` additionally diffs `jq .cells` of the output against `ref.cic`.

Regenerating a golden reference is a deliberate act — inspect the diff before overwriting `ref.cic`.

Other checks: `make cppcheck` (writes `errors.org`), `doxygen` for API docs, `sphinx-build docs/source docs/_build` for the manual.

## Architecture

### Three qmake subprojects, built in order

`cic-core` (static lib, all the logic) → `cic` (CLI) → `cic-gui` (Qt widget viewer). Both executables link the same core. **qmake does not glob**: a new `.cpp`/`.h` must be added to `HEADERS`/`SOURCES` in `cic-core/cic-core.pro` or it will not be compiled.

### The JSON-to-meta-object engine (the thing to understand first)

`cic-core/src/core/design.cpp` is the whole language runtime. There is no parser for a DSL — **JSON keys are Qt meta-method names**:

1. `"class"` is looked up with `QMetaType::type()`/`QMetaType::create()` and instantiated as a `Cell*`. Default class is `cIcCore::LayoutCell`.
2. Every other key in the cell object is matched against the class's `Q_INVOKABLE` methods and `Q_PROPERTY`s and invoked with the JSON value as `QJsonArray`, `QJsonObject`, or `QJsonValue` (`Design::runMethod`). A method taking no parameters is invoked with none — passing an argument to it fails silently on newer Qt.
3. A plural key (`addDirectedRoutes`) whose singular form (`addDirectedRoute`) exists as a method iterates the array, calling the method once per element.
4. Keys matching `^new|inherit|leech|class|name|before.*|after.*|comment|decorator|spiceRegex` are reserved and never invoked directly.

So **adding a new JSON command = adding a `Q_INVOKABLE` method**, and **adding a new cell class = `Q_DECLARE_METATYPE` in the header + `qRegisterMetaType<...>("Namespace::Class")` in the `Design` constructor + the `.pro` entries**. Miss the registration and you get `Error(design.cpp): did not find <class>` at runtime, not a compile error.

### Cell lifecycle

For each cell, in order — parents' hooks always before the cell's own, decorators after both:

```
afterNew → <instance methods> → beforePlace → place() → afterPlace
         → beforeRoute → route() → afterRoute → addAllPorts()
         → beforePaint → paint() → afterPaint
```

`place()`, `route()`, `paint()` are the virtuals a `Cell` subclass overrides; `before*`/`after*` are the JSON escape hatches. `inherit` walks a parent chain (parents' JSON is replayed onto the child first); `leech` pulls in one other cell's JSON without a class relationship; `decorator` inserts a `LayoutCellDecorator` (e.g. `ConnectSourceDrain`) into every stage.

Cells are registered in a **global static map** `Cell::_allcells` keyed by name — cell names are global across all included files, and order matters (a cell cannot be referenced before it is created; `include` files are read sequentially).

### Geometry model

- `SimpleRect` (plain ints) ← `Rect` (adds `QObject`, layer, net, `updated()` signal) ← `Cell` ← `LayoutCell`. Cells *are* rectangles; a cell's bounding box is recomputed from children via the `updated()` signal.
- Coordinates are **integers in Ångström** (`Rules::toMicron` divides by 1e4). `Rect::snap` quantizes to a 5-unit grid.
- **`top()` is `y2`, `bottom()` is `y1`** — y grows upward. This pair was inverted once and broke mirroring, track routing and guard rings while DRC stayed clean; see the comment block in `rect.h`.
- `Rules` is a singleton (`Rules::getRules()`) populated once by `Rules::loadRules(techfile)` before any cell is built. Rule values are scaled by `gamma`. `Rules::getConnectStack` walks the `previous`/`next` layer chain in the tech file to build via stacks.

### Routing

`Route` (`core/route.cpp`) is the largest piece of behaviour. Route commands are strings parsed by regex into `<start path regex><route type chars><stop path regex>`, e.g. `"XA1:S-|--XB2:S"`; the middle characters select a `RouteType` (`-`, `|`, `<`, `>` combinations → STRAIGHT, U_LEFT, STRAP, …). A fourth array element is an options string, itself scraped by regex for `track4`, `3cuts`, `offsethigh`, etc.

- `addDirectedRoute` — hierarchy-path based, brittle, use when connectivity routing cannot reach.
- `addConnectivityRoute` — matches *net names* against the node graph built from the SPICE netlist; preferred.

`docs/source/routing/` documents the syntax with rendered examples; `tests/routes/routes_svg/` has one SVG per routing feature and doubles as a visual regression corpus.

### Output

`Design::toJson()` → `writeJsonFile()` writes `<library>.cic` with an `info` block (version, hash, arguments). All `Cut` objects created during routing are hoisted to top-level cells first. The `cIcPrinter::DesignPrinter`/`Cics` classes are the remnants of the old multi-format printers.

## Conventions

- Lines in the object JSON starting with `//` are stripped before parsing — the input is JSON-with-comments, so hand-editing with a strict JSON tool will fail.
- `"prefix"` (option or `--prefix`) prepends to every cell name, for shipping variants of the same design.
- `"topcells"` marks entry points; cells not reachable from them are still emitted but flagged unused.
- macOS: the Makefile's `strip_agl` target removes `-framework AGL` from the generated makefiles because Qt's mkspecs still reference a framework Apple deleted after SDK 15. Do not "clean up" that hack.
- The CI image is `wulffern/cic_qt:latest` (built from the `Dockerfile`); `make ci`/`make cirun` build and shell into it.
